## PR-1 — The dash key (FR-003)

1. **`palette.ts` gains** `VocabularyEntry`, and `labelCollision`, `pairCollision`, `freePair` move
   in from `kind.ts` / `KindField.tsx`. All three are pure over `VocabularyEntry`; none needs
   tldraw.
2. **`pairCollision` compares keys**: `e.dash === dash`, not `e.dash === KIND_DASHES[dash]`. Without
   this the function returns `null` for every query and the WCAG 1.4.1 refusal retires silently.
   Verified by execution in review: `pairCollision('orange','solid', seeds)` → `null` before the
   fix, `'data'` after, with `orange/dotted` and `exceptId:'data'` still correctly `null`.
   **No re-export from `kind.ts`.** `kinds/index.ts` already does `export * from './palette'`, and
   the only two importers go through the barrel or `./index` — nothing imports `./kind` directly —
   so both stay green with no shim. A re-export would also leave `kind.ts`, which imports three
   tldraw packages, advertising the tldraw-free functions, which is the back door the fence closes.
3. **`freePair(entries)`** returns `{colour,dash} | null`; no `taken` argument. `KindField`'s two
   call sites keep today's first-pair fallback on `null`.
4. **`overlayVocabulary` stops resolving the dash** — two lines.
5. **`resolveKind` resolves both**, using `Object.hasOwn(KIND_DASHES, entry.dash)` for the unknown
   check. A truthiness or `=== undefined` check makes every solid kind, `data` included, render
   unresolved, because `KIND_DASHES.solid` is legitimately `undefined`.
6. **`dashKeyOf` deleted** from `KindField.tsx`; the edit form reads `entry.dash` directly.
7. **Tests**: `overlay.test.ts`, `kindVocabulary.test.ts`, `connectionStrands.test.ts`,
   `KindField.test.tsx`, `palette.test.ts`. Plus two new ones: `pairCollision` still refuses after
   the change (the
   mutation is step 2 reverted), and the **fence test** — rewritten, because the first draft's
   wording is false of `document.ts` today (it reaches `@tldraw/tlschema` through `./shapes/node`).
   Two achievable properties instead: `palette.ts` resolves no import at all, and no `src/shared`
   source resolves a relative import outside `SHARED_DIR` — the hole `shared-imports.test.ts:179`
   leaves by `continue`ing past every relative specifier at `:180`. **With planted fixtures**, in
   the style of `filesDeclaringShapeTypeLiteral` — the tldraw check beside it is inline, so this
   needs its OWN extraction: a graph escaping through a two-hop relative chain, and a clean one
   asserting silence.
8. **The literal enumeration is replaced by a DERIVED guard**, because a hand list rots and because
   `tsc` only reddens the three `dash: undefined` sites — the five `dash: '12 5'` / `'7 4'` literals
   stay type-valid lies that silently degrade to the unresolved look while their tests still pass
   on `markerKey`. Fixtures are built through `overlayVocabulary` with *record* literals, as
   `convertPolicy.test.ts` already does (immune by construction), or a derived assertion checks
   every fixture entry's `dash` is a `KIND_DASHES` key.
   **Named by hand because it INVERTS rather than updates:** `overlay.test.ts`'s
   `it('resolves a seed dash to its SVG value, not its key')` asserts `data.dash === undefined` and
   `permission.dash === '7 4'`. Its title becomes a lie and its expectation flips. A generic "update
   this file" instruction loses exactly this.
9. Where `overlay.test.ts`'s `labelCollision` / `pairCollision` describe blocks go after the move:
   into `palette.test.ts`, with the functions.

## PR-2, commits 2–4 — the format, the room, the sweep

### Phase 3 — the format (FR-001, FR-002, FR-004)

- `DocumentKind`; optional `kinds` on `DocumentConnection` and `DiagramDocument`; `DOCUMENT_VERSION`
  → 4; `SUPPORTED_DOCUMENT_VERSIONS` → `[1,2,3,4]`.
- **Fix the `actorId` guard**: `raw.version !== 3` → `raw.version < 3`, plus a criterion-backed test
  that a v4 document with an `actorId` is accepted. Pre-existing bug, triggered only by the bump.
- Two new guards (`document.kinds`, `connections[i].kinds`), four-guard order pinned and asserted.
- Validation: self-containment against the document's own effective vocabulary; the five
  corruption-class rules one test each; closed `colour`/`dash`; a two-entries-share-a-pair document
  **accepted**; version error text pinned.
- **`'kinds'` added to `TOP_LEVEL_KEYS` and `CONNECTION_KEYS`**, and a per-entry key allowlist.
  **The reason is the opposite of the obvious one**: the version guards run *before* `unknownKey`,
  so a v1–v3 document already reports `requires version 4` without these — they are needed so a
  **valid v4** is not rejected `unknown key`. Stated because a builder who believes the inverted
  reason may place the new guards *after* the key checks, which is where FR-004's pinned text breaks.
- The id pattern is **anchored**: `^[A-Za-z0-9_-]+$`. Unanchored it accepts `read replica`.
- `document.ts` imports `./kinds/palette`, **never** the `./kinds` barrel — prose only, since the
  barrel reaches `@tldraw/tlschema`, which is on the shared allowlist, so nothing catches it.
- **With no `vocabulary` argument, each connection's kinds are filtered to the `SEED_KINDS`
  labels**, with a test. Otherwise a Phase 4 test that builds a kinded connection and omits the
  parameter emits a document `parseDocument` rejects — from the one function whose contract forbids
  exactly that.
- **A connection's `kinds` must arrive in normal form**: `["b","a"]` and `["a","a"]` rejected.
  `normaliseKinds` is importable from `./shapes/connection`, which `document.ts` already imports.
- **Non-array `kinds` at either site** rejected, with the same defensiveness the module already
  documents for its other collections.
- **`upgradeV3` MOVES THE VERSION AND NOTHING ELSE.** `upgradeV1` injects `scenes: []`, and a
  builder copying that shape writes `kinds: []` — making `'kinds' in result.document` true for every
  upgraded v3 (FR-001's absent-vs-empty fails) and making a v3 import *clear* the authored vocabulary
  (FR-006's absent case fails). The `'kinds' in …` test pins it.
- **`upgradeV3` plus `if (doc.version === 3) doc = upgradeV3(doc)`.** Survivable today because every
  guard reads `raw.version`, which is what makes it easy to skip — and `upgradeV2`'s docblock argues
  that the composition chain is what a v4 extends. Leaving it stopping at 3 is expensive at v5.
- **`fromDocument`'s connection props: `kinds: [...(connection.kinds ?? [])]`** — spread, so no
  record aliases the parsed document's array, replacing the hardcoded
  `kinds: []`. One line, and the line the whole round trip hangs on: without it import silently
  drops every connection's kinds and nothing catches it until Phase 4's round-trip test, two phases
  later. The v3 blob stays byte-identical through it (v3 documents carry no kinds, so `?? []` still
  yields `[]`), so the "an edit to a blob is the finding" rule covers the v3 one too.
- `fromDocument` returns `kinds?:` — optional, so the v1/v2 `EXPECTED` blobs stay byte-identical.
  **If either blob needs an edit, that is the finding, not the fix.**
- `toDocument(..., vocabulary?)` — omitting it omits the key.

### Phase 4 — export and import (FR-002's invariant, FR-005, FR-006)

- Export reads `vocabularyEntries(editor)` (label-keyed and memoised) — not `overlayVocabulary`,
  which would emit duplicate labels and trip the panel's measured perf warning.
- Synthesis for an unresolved word, **in two passes** and placed deliberately: after the
  `documentConnections` loop so the two `continue` filters have already dropped half-bound and
  non-documentable connections, and before the return. **Two passes is forced**: synthesis can DROP
  a word, so a connection's `kinds` cannot be finalised inside the loop — a single pass writes the
  word and then fails to define it, emitting a document `parseDocument` rejects, which is the one
  thing this module's contract forbids. The second pass removes dropped words and deletes the
  `kinds` key when an array empties.
- The words are sorted with **plain `<`**, the comparator `normaliseKinds` and `overlayVocabulary`
  both use and for the reason both docblocks give; anything else and two clients diverge on a
  mixed-case label, against this FR's own byte-identical criterion.
- id = `unresolved-` + slug, 64 chars, numeric suffix on collision; fold each entry in before
  choosing the next; drop only when `freePair` returns `null` or the label is empty.
- The invariant test over the named cross product: {0,1,2 records} × {rename a built-in, add a kind,
  duplicate a label, duplicate a pair, swap two built-in labels}.
- Round-trip pair: export→import→export identical; two exports of an unchanged room identical.
- **A room that never created a kind exports the three built-ins**; **a renamed built-in exports
  under its new label once and the old label appears nowhere**; **the label total order** — three
  named tests, not three things implied by routing through `vocabularyEntries`.
- **The merged-connection regression pin**, building a real merged pair. The spec labels it as
  unable to fail against a plausible implementation, which is precisely why a plan drops it.
- `importDocument` replaces the authored vocabulary inside the existing `markHistoryStoppingPoint` +
  `run`, writing only what differs from the built-in of the same id, removing the surplus.
- **All three import cases need a NON-EMPTY precondition** or each passes trivially: at least one
  authored record, and for the untouched case one whose id the document does not mention.
- **Three distinct cases, not one**: key **absent** (every upgraded v1/v2/v3) changes no record;
  `kinds: []` clears the authored vocabulary back to the built-ins; a vocabulary that **already
  matches** writes nothing and leaves record identities unchanged. "Removing the surplus" read
  literally collapses the first two and destroys the reason the key is optional, and "differs from
  the built-in" is a different rule from "differs from what is already there".
- **A v3 import leaves every `diagramKind` untouched and creates none** — the criterion the spec
  flags as diverging from scenes, and therefore the one most likely to be assumed.
- `vocabularyWouldChange` as the dialog's third trigger term; `vocabularyLostOnImport` for the
  sentence; lead clause gains a third branch; up-to-three-then-count; an add-only wording.
- **Both depend on the pending document, not just the editor**, so neither can copy the panel's
  three existing `useValue(…, [open, editor])` derivations: the trigger is computed inline from
  `result.document` in `onImportClick`, the sentence from `pending`. Copying the pattern gives a
  stale closure that looks right.
- `DiagramIOPanel.test.tsx`'s mock factory gains both and loses `connectionsWithUndocumentedKinds`
  (factory, `beforeEach`, three assertions) — the first thing this phase hits.
